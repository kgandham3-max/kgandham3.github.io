ARGUS

Operational

AI-powered regression platform

Across the 11 production websites I own delivery for, catching a broken page used to mean a person clicking through it, twice a day, every day. That was roughly five hours of team time daily, and even then, only the major sections got checked.

11websites covered
4×full passes daily
5+ hrsteam time freed, per day

ARGUS replaced that manual sweep entirely. It now runs full content validation across every page on all 11 sites, with an initial layer of functional checks layered in, four times a day rather than two, timed to both India and US working hours so nothing sits unchecked overnight.

I architected and built ARGUS myself, the same instinct behind the Pre-UT quality gate I designed earlier in this role: find where manual effort is standing in for something that should be systematic, then remove the ceiling instead of working harder inside it. ARGUS stands for Autonomous Regression, Governance and Unified Surveillance, and it is designed as a local-first platform, so the same foundation can grow into baseline management, visual comparison, and release-aware validation.

The design goal is simple to say: ARGUS understands what a release is supposed to change, watches what actually changes, and flags it when the two disagree. That includes catching unexpected blast radius, like a story that touches the account page but also shifts the login page. Release validation is the piece I'm building next, so the check happens as part of the cutover itself instead of as a manual step after it.

Sherpa

Live, still evolving

A platform-agnostic job-application agent

A real job search asks for more than one person can keep up with: parsing postings, tailoring materials, and navigating a different application system every time. Sherpa runs the whole loop locally, no cloud AI costs, no data leaving the machine.

$0in API costs
1generic engine, not one per platform

A local LLM scores fit against my profile, then Sherpa walks the real application flow on whatever platform the posting routes to, Workday, Greenhouse, or something else entirely, using one generic scan-and-fill engine instead of custom code per platform.

What I didn't automate mattered as much as what I did. Every application runs through guardrails: a fit threshold, a salary floor, duplicate prevention, and a review queue for anything the system isn't confident about, plus a kill switch that stops the whole pipeline instantly.

Most of the real engineering was building visibility into failures that don't announce themselves, a button that visually exists but can't be located doesn't throw an error, it just quietly moves on. I fix those while it keeps applying. Discovery runs on LinkedIn today. Next up: other job boards, and Gmail integration so every application is tracked end to end.
